# Application updates

**Goal**: on launch, check GitHub Releases, tell the user a new version exists, and — with their
consent — install it and restart cleanly, without ever creating a privilege-escalation path.

Constraint: **the app is not OS code-signed** on any platform. See
[../decisions/0005-on-demand-elevation.md](../decisions/0005-on-demand-elevation.md) for what that
forces.

## Two signatures, do not confuse them

| | Updater signature (minisign) | OS code signing |
| --- | --- | --- |
| What | Ed25519 key pair; public key compiled into the app | Authenticode / Apple Developer ID + notarization |
| Cost | free | ~$99/yr Apple, ~$200–400/yr Windows OV |
| Tauri v2 | **mandatory, cannot be disabled** | not required for the updater to function |
| Protects | the update artifact is genuinely ours and unmodified | the OS trusts the binary on first launch |

We ship without the right-hand column and keep the left-hand one. Update *integrity* is therefore
intact; what we lose is first-launch friendliness.

## Feed

- Endpoint: `https://github.com/<org>/MixEngine/releases/latest/download/latest.json` — the stable
  asset redirect, **not** the GitHub API (which is rate-limited to 60 requests/hour per IP for
  unauthenticated callers).
- `latest.json` is generated by `tauri-action` at release time and lists version, notes, pub date,
  and a signed artifact URL per platform/arch.
- Check on launch, then at most once every 24 h. Failures are silent — an offline machine must never
  see an error dialog.
- A "Check for updates" action in Settings forces an immediate check.

## User flow

1. Update found → non-blocking notification, never a modal that interrupts work.
2. The user sees version, size, and release notes rendered from the feed.
3. **Explicit consent required.** Updates are never silent, because installing one restarts the
   daemon and therefore every supervised service.
4. On accept: stop supervised services in reverse dependency order → download → verify minisign →
   install → relaunch → restart the services that were running.
5. "Skip this version" and "Remind me later" are both real options and are remembered.

Never update while a supervised service is under load without asking. A developer mid-request losing
their database is worse than a delayed update.

## What must never auto-update

`mixengine-elevate` is excluded from the automatic path. It is installed once to a root-owned
location, and updating it requires its own explicit elevation prompt with a minisign check performed
**inside** the elevated context, against a public key pinned in the currently installed copy.
The daemon and elevate binary negotiate a protocol version; an old elevate keeps serving the
operations it knows while the app asks the user to upgrade it.

This is the single most important rule on this page: an auto-updated binary that runs as root, with
no OS signature, is a local privilege-escalation vector.

## Platform reality when unsigned

**Linux** — no obstacle. AppImage/deb/rpm unsigned is unremarkable.

**Windows**
- SmartScreen shows "Windows protected your PC". Reputation is keyed to the binary hash, so **every
  release resets it** — the warning recurs after each update, it does not train away.
- Install per-user (`%LOCALAPPDATA%\Programs\MixEngine`, NSIS `perMachine: false`) so updates need no
  UAC at all.
- The updater exits the app so the installer can replace locked files; this is normal Tauri
  behaviour on Windows.
- **Watch for**: Defender heuristics flag hosts-file modification as
  `SettingsModifier:Win32/HostsFileHijack`, and an unsigned binary doing it is far likelier to trip
  them. Test on a machine with full Defender enabled before release.

**macOS** — the painful platform, but the pain is at **first install**, not at update:
- Gatekeeper blocks the downloaded `.dmg`. Since macOS 15 Sequoia the Control-click → Open shortcut
  is gone; the user must go to System Settings → Privacy & Security → "Open Anyway". Expect drop-off
  here, and document it prominently.
- Apple Silicon requires at least an ad-hoc signature to execute; the linker supplies one at build
  time, so the app runs.
- Updates downloaded by the already-running app are generally not quarantined, so relaunch works.
  **Verify this empirically before relying on it** — MixDB already ships this way and is the best
  available evidence.

Recommended sequencing: ship Linux and Windows unsigned first; add macOS when a Developer ID is
available. On macOS the certificate is effectively table stakes for distribution — not because of the
updater, but because of Gatekeeper.

## Acceptance criteria

- A tampered artifact fails the minisign check and is refused, with the reason shown.
- An offline launch produces no error and no delay to startup.
- Accepting an update restarts exactly the services that were running before it.
- `mixengine-elevate` is never replaced without an elevation prompt.
- Declining an update leaves the app fully functional and does not re-prompt for that version.
